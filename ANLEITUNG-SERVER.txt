================================================================================
SCHICHTWERK AUF DEM WINDOWS-SERVER – ZENTRALE ANLEITUNG
================================================================================

Es gibt ZWEI Wege, Schichtwerk dauerhaft auf einem Windows-Server zu betreiben.
Beide starten automatisch mit Windows und brauchen KEIN offenes Fenster.

  WEG 1: Windows-Dienst (empfohlen, kein Docker notwendig)
  WEG 2: Docker (falls auf dem Server bereits Docker verfuegbar ist)

Wenn Sie unsicher sind: WEG 1 verwenden.


--------------------------------------------------------------------------------
SCHRITT 0: Richtigen Ordner sicherstellen
--------------------------------------------------------------------------------

Ein sehr haeufiger Fehler: ein alter/anderer Ordner (z. B. nur mit "server.js")
wird gestartet statt des echten Schichtwerk-Projekts.

1. Aktuellen Stand laden:
   https://github.com/xXLaser/Schichtplaner/archive/refs/heads/cursor/schichtplaner-tool-94b2.zip

2. ZIP nach genau diesem Ort entpacken:
   C:\Schichtwerk

   Danach MUSS direkt vorhanden sein (nicht in einem Unterordner!):
     C:\Schichtwerk\package.json
     C:\Schichtwerk\WINDOWS-DIENST-INSTALLIEREN.bat
     C:\Schichtwerk\Dockerfile
     C:\Schichtwerk\src
     C:\Schichtwerk\prisma

   Falls das alles erst in einem Unterordner liegt (z. B.
   C:\Schichtwerk\Schichtplaner-xxx\...): den Inhalt dieses Unterordners
   eine Ebene nach oben nach C:\Schichtwerk verschieben.

3. Doppelklick auf PRUEFEN.bat -> es muss ueberall [OK] stehen.


--------------------------------------------------------------------------------
WEG 1: WINDOWS-DIENST (ohne Docker) – EMPFOHLEN
--------------------------------------------------------------------------------

1. Node.js LTS installieren, falls noch nicht vorhanden:
   https://nodejs.org/

2. Im Ordner C:\Schichtwerk:
   Rechtsklick auf WINDOWS-DIENST-INSTALLIEREN.bat
   -> "Als Administrator ausfuehren"

   Das Skript macht automatisch:
     - laedt einmalig ein kleines Hilfswerkzeug (nssm) herunter
     - baut die Anwendung (kann beim ersten Mal einige Minuten dauern)
     - richtet die Datenbank ein und laedt Beispieldaten
     - installiert einen Windows-Dienst namens "Schichtwerk"
     - startet ihn sofort

3. Nach Abschluss im Browser testen:
   http://localhost:3000/api/health
   http://SERVER-IP:3000/api/health

4. Fertig. Der Dienst laeuft ab jetzt automatisch bei jedem Windows-Start,
   auch ohne angemeldeten Benutzer und ohne offenes Fenster.

Verwaltung:
  - services.msc oeffnen, dort "Schichtwerk" suchen
    (Starten/Stoppen/Neustarten moeglich)
  - Logs liegen unter:
    dist-windows-dienst\dienst-log.txt
    dist-windows-dienst\dienst-fehler.txt

Dienst wieder entfernen:
  WINDOWS-DIENST-ENTFERNEN.bat (als Administrator)

Update auf eine neue Version:
  1. WINDOWS-DIENST-ENTFERNEN.bat ausfuehren
  2. Neuen Stand ueber die alten Dateien kopieren
  3. WINDOWS-DIENST-INSTALLIEREN.bat erneut ausfuehren


--------------------------------------------------------------------------------
WEG 2: DOCKER
--------------------------------------------------------------------------------

Docker auf einem Windows SERVER (nicht Windows 10/11) benoetigt zusaetzlich
WSL2 oder Hyper-V. Das richtet meist die IT ein. Wenn Docker bereits laeuft:

1. Eingabeaufforderung im Ordner C:\Schichtwerk oeffnen
2. Ausfuehren:

     docker compose up -d --build

3. Beim ersten Start passiert automatisch:
   - Datenbank-Migrationen
   - Beispieldaten, falls die Datenbank leer ist
   - Server startet auf Port 3000

4. Test:
     http://localhost:3000/api/health

5. Neustart nach Server-Reboot: Docker startet den Container automatisch
   erneut (restart: unless-stopped in docker-compose.yml).

Nuetzliche Befehle:
     docker compose logs -f        (Logs live ansehen)
     docker compose down           (Container anhalten)
     docker compose up -d --build  (nach Update neu bauen und starten)

Die Datenbank liegt in einem Docker-Volume ("schichtwerk-data") und bleibt
bei einem Update/Neubau erhalten.


--------------------------------------------------------------------------------
FIREWALL (bei beiden Wegen notwendig)
--------------------------------------------------------------------------------

Windows-Firewall -> Erweiterte Einstellungen -> Eingehende Regeln
-> Neue Regel -> Port -> TCP -> 3000 -> Zulassen

Wichtig: den PORT freigeben, nicht nur das Programm "Node.js" oder "Docker".


--------------------------------------------------------------------------------
DIAGNOSE
--------------------------------------------------------------------------------

Im Browser (am Server selbst oder von einem anderen PC im Netzwerk):

    http://SERVER-IP:3000/api/health

Zeigt "ok": true und eine Mitarbeiterzahl -> alles funktioniert.
Zeigt einen Fehler -> der Fehlertext dort beschreibt bereits die Ursache.
